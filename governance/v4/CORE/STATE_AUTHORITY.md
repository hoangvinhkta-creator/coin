# CORE — STATE AUTHORITY (V4.3)

Status: CANONICAL (V4.3 overlay)
Layer: CORE — project-agnostic.

## Single Source Of Truth

Every class of state has exactly one canonical holder. Where an existing repository
already holds a class of state, V4.3 **maps** onto that holder rather than duplicating it.

| State class | Rule |
|---|---|
| Project profile | one file, declares governance depth |
| Capability registry | capabilities, lineage roots, owners |
| Project state / roadmap | one roadmap source of truth; derived views are generated |
| Production paths | declared, never inferred |
| Risk register | one register |
| Completion gates | live with the task they gate; FROZEN gates are immutable |
| Review budget ledger | budget per capability lineage root |
| Project decisions | Owner Decisions, append-only |
| Hardening backlog | hardening findings + re-trigger conditions |
| Session handoff | per-session record |

Duplicating a source of truth is a governance defect, not redundancy.

## Reading State

An agent reads state; it does not reconstruct state from conversation memory. Questions
about progress, current step, remaining work or next step are answered from the canonical
state file, not from narrative.

## Writing State

State changes are written to the canonical holder and to nothing else. Generated views are
regenerated by their generator, never hand-edited.

## Migration Uncertainty

When adopting V4.3 into an existing repository, historical values may be insufficient to
reconstruct a canonical field (most often budget). In that case record:

    MIGRATION_UNCERTAINTY

with what is known, what is missing, and what would resolve it. Never fabricate a value,
and never reset a budget to zero merely because an adoption has just occurred. If the
Owner must set a new value, record `OWNER_DECISION_REQUIRED`.

## Vacuous Validation

A validator that reports success while having examined nothing is not a passing validator.

    "Checked 0 records" is not a meaningful PASS.

Validators must report the size of the set they examined, and a zero-sized set on a
non-empty repository is a validator defect to be routed, not a green light.
